# 在 macOS 上使用国网内网 U 盘

国网（国家电网）内网配发的 **EAGET EDP 加密 U 盘**，出厂只支持 Windows：插到 Windows 上由厂商的内核过滤驱动把加密块设备翻译成普通盘符，插到 Mac 上就只剩一个 10.5 MB 的只读「启动区」，**56.6 GB 的交换区完全看不见**。

本项目让这块盘在 macOS 上能用：用户态解密交换区 → 挂载成 `/Volumes/交换区` → 编辑后加密写回 → 逐扇区回读校验。
纯本机运行，不联网、不上传、不碰保密区。

```
Windows 下的原始链路            macOS 上的替代链路（本项目）

密文扇区                       密文扇区
   │ EdpEDisk.sys（内核过滤驱动）     │ 用户态 SM4-CTR 解密
   ▼                                ▼
明文块设备 ──► 盘符 Z:         本机稀疏镜像 ──► /Volumes/交换区
   ▲                                │
   └──── 写入即加密                 └──── 保存时加密写回 + 回读校验
```

## 为什么 Mac 上必须换一种做法

| 障碍 | 后果 |
|---|---|
| macOS 开了 SIP，不让加载第三方 kext | 厂商的 `EdpEDisk.sys` 那套机制搬不过来 |
| 没有 Apple 签名的 DriverKit entitlement | 也做不了替代的 DEXT 驱动 |
| 因此文件系统无法直接坐在加密设备上 | 只能在用户态做等价模拟 |

用户态模拟的代价是中间多一层本机副本，所以**保存必须有「写回」这一步**，不存在零延迟方案；写回前会把受影响扇区的原始密文存进本机回滚记录，写完逐扇区回读比对。

## 这块盘的三个区域与本项目的关系

| 区域 | 位置/大小 | 本项目 | 说明 |
|---|---|---|---|
| 启动区 | 10.5 MB，FAT32 | 只读使用 | macOS 原生可见；放厂商 Windows 客户端与 `EDP交换区.command` 入口 |
| **交换区** | 起始 LBA 20480，56,598,069,248 字节（约 56.6 GB） | **读写（核心目标）** | SM4-CTR，exFAT，元数据版本 `0x206` |
| 保密区 | 更靠后 | **不接触** | 需要更高权限，本项目不做任何访问 |

不格式化、不修复分区、不改固件/口令/设备绑定。交换区口令由你本机键盘输入，只进内存和钥匙串，不写明文、不进日志、不做口令猜测。

## 项目提供的三种用法

| 工具 | 形式 | 适用场景 |
|---|---|---|
| **挂载器** `edp-mount` | Swift 通用二进制 + 双击脚本 | 日常使用：把交换区挂到访达当普通磁盘读写 |
| **只读浏览器** | Python，本机网页 | 只想把文件拷出来：不挂载、不写盘，零写风险 |
| **读写工作区** | Python，镜像 + 回滚记录 | 需要精细控制写回、想留回滚点、批量搬运 |

典型用法：内网机器上的报表、截图、文档放在交换区里，插到 Mac 上挂载后直接编辑，保存回写再插回内网机器使用。

## 快速开始

### 使用者（三步，一次配置）

1. 插入 U 盘，等访达出现「启动区」。
2. 双击 `outputs/启动程序源码/安装免密码.command`（只需一次）：输一次 Mac 管理员密码安装本机帮助程序，再输一次交换区口令存进钥匙串。
   免密是通过一条只允许执行 `/usr/local/libexec/edp-mount` 的 `sudoers` 规则实现的，不是给整个程序提权。
3. 以后双击 `EDP交换区.command` → 自动挂载到 `/Volumes/交换区`；退出时用菜单「立即保存 / 保存并退出 / 保存并弹出」。

卸载：`sudo rm /etc/sudoers.d/edp-mount /usr/local/libexec/edp-mount` 加 `security delete-generic-password -s edp-exchange-password`。
完整操作细节见 [使用说明](outputs/启动程序源码/使用说明.txt)，技术原理见 [技术文档](docs/reports/技术文档-EDP交换区macOS客户端.md)。

**保存行为**：刷新 → 加密写入 → 本次所有改动区间**回读校验**；短读或校验不一致立即返回失败，失败不继续退出、不弹盘，避免把坏数据当成成功。

### 开发者

```bash
./scripts/build.sh     # swiftc 分别编 arm64 / x86_64，lipo 合成通用二进制
./scripts/verify.sh    # 结构 + 哈希 + Python 语法 + 工作区干净度自检
```

Python 工具（只读浏览器 / 读写工作区）需要本机隔离环境，按各自目录下的 `requirements.txt` 重建：

```bash
python3 -m venv work/analysis-env
work/analysis-env/bin/pip install -r "outputs/交换区只读浏览器/requirements.txt"
```

## 实现要点

- **算法移植**：SM4-CTR 数据解密 + 元数据解密/校验（MD5 派生、EDP 变体 CRC32），与 Windows 客户端结果逐字节比对通过。
- **设备识别**：`VID 0x0DD8 / PID 0x2005`，用启动区里 `EdpEDisk.exe` 的 SHA256 做设备指纹校验，指纹不符直接退出。
- **挂载**：解密到本机稀疏镜像（逻辑 56.6 GB、实际约 12 MB，位于 `~/Library/Caches/edp-mount/`），再由 `hdiutil` 挂载。
- **写回**：只写本次改动区间；写前把原密文存进回滚记录（SQLite），写后回读比对。
- **权限**：帮助程序仅在核验设备后打开原始设备，交替使用最小权限；口令经钥匙串读取，不出现在命令行参数里。

## 数据与隐私

仓库只收源码、文档和可复现证据。**设备镜像、真实设备数据、厂商二进制、本机环境一律不入库**：

| 排除项 | 原因 |
|---|---|
| `outputs/交换区读写工作区/` | 稀疏镜像逻辑容量 53 GiB ×2 与回滚数据库，含真实数据 |
| `work/rw-tests/` | 读写回归工作区，含真实数据 |
| `work/usb-copies/` | 厂商 Windows 客户端与驱动二进制，版权归厂商 |
| `outputs/交换区导出/` | 从真实交换区导出的业务文档 |
| `work/device-metadata/*.bin` | 真实设备身份与分区原始抓取 |
| `work/analysis-env/`、`work/exfat-upstream/` | 本机 Python 环境、第三方上游源码副本 |
| `work/reader-session/`、`*.lock`、`*.sqlite3` | 运行时套接字、锁与回滚数据库 |

逐项文件数、体积与 SHA256 见 [排除文件清单](docs/排除文件清单.json)；用 `python3 scripts/check_excluded.py` 在原始工作目录复算比对。说明见 [发布范围与敏感数据](docs/发布范围与敏感数据.md)。
