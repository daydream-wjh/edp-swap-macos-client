# 加密 U 盘客户端静态分析：首批结果

本报告来自对实际文件的独立检查。仅分析本地副本，没有运行 Windows 客户端、认证、修改固件或向 U 盘发送私有命令。Mac 访问目标尚未实现。

## 输入与工具

源文件来自 `/Volumes/启动区`，工作副本在 `work/usb-copies/`。工具为隔离 Python 环境中的 pefile 2024.8.26、Capstone 5.0.9，以及 Python 标准库 zlib。未使用 Ghidra，没有生成高级语言反编译结果；本轮取得的是 PE 结构、资源和 x86 反汇编证据。

## 已确认的关键发现

### 1. 内嵌控制模块可通过标准解压恢复

资源 `SECDISKCTRLDLL/187/2052` 大小为 1,955,810 字节。主程序在首选映像地址 `0x0040e565` 附近定位此资源，在 `0x0040e602` 起扣除 170 字节头部，并在 `0x0040e6ab` 调用数据处理函数，再于 `0x0040e6d1` 写出结果。

独立验证：资源偏移 `0xaa` 起为有效 zlib 流。Python zlib 解压得到 4,642,657 字节有效 PE32 DLL，版本为 `8198, 2100, 1120, 1896`，OriginalFilename 为 `EdpEDiskCtrl.dll`。

头部记录大小为 4,642,656，与完整解压结果相差一字节。本轮保留全部解压数据，未擅自裁切。完整解压数据 SHA256 为 `acd6b882cf72e91aa5134d3adadcd39c1e77d7d4477a5c672eb333b1636d5a6f`。

DLL 导出恰有 `CreateEdpEDiskCtrlIntObj` 和 `ReleaseEdpEDiskCtrlIntObj`。主程序分别在 `0x0040e9aa`、`0x0040ea0d` 通过 GetProcAddress 查找这两个名字，与提取结果吻合。因此该资源的控制模块身份有直接证据支持。

### 2. 主程序导入表不足以判断驱动依赖

提取的控制模块导入 SETUPAPI.dll，包括 SetupDiGetClassDevsA、SetupDiGetDeviceInterfaceDetailA、SetupDiEnumDeviceInterfaces、SetupDiDestroyDeviceInfoList；也导入 DeviceIoControl、CreateFileA、ReadFile 和 WriteFile。

模块包含 PhysicalDrive/Scsi 设备路径模板、VolumeLock.sys、VolumeLock64.sys、EdpEDisk.sys、EdpEDisk64.sys 路径字符串。更强的结构证据是：控制模块文件偏移 `0x29cd8c` 与 `0x2aa68c` 分别包含可解析的 i386 / AMD64 PE，Subsystem 均为 1（Native）。这是内嵌驱动候选，尚未通过版本、导入和调用链确认其身份及是否必需。

因此，之前根据外层 EXE 未导入 SetupDi、未见驱动名而推断“不依赖随盘驱动”，证据不充分。也不能反过来认定每次交换区登录都需要上述驱动。

### 3. 已定位设备 I/O，但不能直接称为 SCSI 认证通道

主程序中 DeviceIoControl 的直接调用候选位于 `0x0040fc68` 和 `0x0040fd8e`，调用前分别出现控制码常量 `0x002d1080` 和 `0x002d1400`。提取的控制模块还有多处 DeviceIoControl 调用，详见 inventory.json。

这些常量及调用点只证明存在设备控制操作。尚未根据官方头文件逐一解释控制码，也未证明其中任一调用用于口令认证。不能把 DeviceIoControl 本身当作 SCSI pass-through 的证明。

模块日志字符串包含 `CEdpDiskControl::UserLogin`、`WSTUserLogin`、`UserLogoff` 等，为后续调用链分析提供线索；字符串本身不证明认证协议或口令处理方式。

## 对 Mac 可行性的影响

现有证据表明，客户端并非只有外层 EXE：至少还有压缩控制 DLL 和多个内嵌 PE。下一步必须确定交换区正常登录与后续文件访问经过哪些模块，是否需要 Native 驱动，以及设备认证后是否暴露标准卷。现在不能确认 Wine、Windows ARM 虚拟机或原生移植可行，也不能认定全部不可行。

本轮没有尝试密码、提取个人凭据或改变策略。尚无可运行的 Mac 解锁工具。

## 证据与复现

同目录 `静态分析证据/` 提供 inventory.json、control-extraction.json、control-extraction.asm、embedded-pe.json 与两个分析脚本。分析脚本从本地副本读取，生成资源、导入表、版本及直接 IAT 调用候选；extract_control.py 解压上述控制模块。

地址为 PE 首选加载地址下的静态 VA，运行时可能因重定位变化。API 候选由可执行节线性反汇编取得，不是完整控制流图，可能漏掉间接调用或误识别嵌入数据；后续关键结论需逐处验证。汇编摘录起点未必是函数边界，不能把摘录首行当作函数入口。
