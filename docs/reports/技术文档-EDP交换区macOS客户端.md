# EDP 加密 U 盘 · macOS 交换区客户端
## 完整技术文档

版本：2026-10-26
适用平台：macOS 13+（Apple 芯片 / Intel 通用二进制）
装置：EAGET EDP 加密 U 盘（VID 0x0DD8 / PID 0x2005，国网定制版）

---

## 1. 概述

本程序在 macOS 上实现对「EDP 加密 U 盘」**交换区**的读写访问，并将其挂载到访达，
使这台原本只能在 Windows 客户端下使用的加密盘，在 Mac 上表现得接近普通 U 盘。

**范围边界**

| 区域 | 是否支持 | 说明 |
|---|---|---|
| 启动区（10.5MB FAT32） | 只读使用 | macOS 原生可见，用来放启动脚本和 Windows 客户端 |
| **交换区（约 56.6GB）** | **读写** | 本项目的目标区域，SM4 加密 |
| 保密区 | **完全不触碰** | 需要更高权限，本项目不做任何访问 |
| 固件 / 口令 / 绑定信息 | 不修改 | 全程只读元数据 |

**不做什么**：不格式化、不修复分区、不改设备绑定、不破解保密区。

## 2. 问题定义：为什么需要这套东西

### 2.1 Windows 下的工作方式

Windows 客户端由两部分组成：

- `EdpEDisk.sys` —— 磁盘过滤驱动（内核态）
- `EdpEDiskCtrl.dll` / `EdpEDisk.dll` —— 用户态控制与密钥派生

驱动把加密块设备"翻译"成明文块设备，Windows 的文件系统直接在上面跑，
所以用户看到的就是一个普通盘符。写入即加密进闪存，没有中间副本。

### 2.2 macOS 的困境

macOS 没有这块盘的驱动，而且：

- 系统开启了 SIP，无法加载第三方 kext
- 没有 Apple 签名的 DriverKit entitlement，无法做 DEXT
- 因此 **无法**让 macOS 的文件系统直接坐在加密设备上

结论：只能在**用户态**做等价模拟。

### 2.3 用户态模拟的基本模型

```
U 盘（密文） --解密--> 本机稀疏镜像（明文） --挂载--> /Volumes/交换区
                              ↑                            |
                              +-------- 编辑后加密写回 -----+
```

因为中间多了一层副本，所以必须有一个"写回"步骤：
**这是所有用户态方案的固有代价，物理上无法做到零延迟。**

## 3. 逆向结论：盘上的数据结构

### 3.1 整体布局

| LBA | 内容 | 说明 |
|---|---|---|
| 0 | MBR | 一个分区，类型 0x0B，起始 LBA 63，长度 20417 扇区 |
| 1–62 | 保留区 | 标签、元数据、设备标识等 |
| 63–20479 | 启动区 | FAT32，明文，Windows 客户端所在 |
| 20480+ | 交换区 | SM4 密文，exFAT 文件系统 |
| 末尾 | 保密区 | 本项目不访问 |

元数据集中在**前 64 个扇区（32KB）**里，客户端只需要读这一段就能拿到全部参数——
这是它能在普通用户态下工作的关键。

### 3.2 元数据头（扇区 4 起）

第一个关键结构在偏移 2048（LBA 4），格式是一个 ASCII 标记：

```
$$$<十进制数字>$$$
```

数字记作 `v`。紧接着从偏移 24 开始，是 **244 个 uint16（小端）**，
它们被一个滚动掩码异或混淆过。解混淆算法：

```
mask = ((v & 0xFFFF) ^ (v >> 16)) & 0xFFFF
for k in 0..243:
     word[24 + k*2] ^= mask
     mask = (mask + 255 - k) & 0xFFFF
```

解出后取 `h = bytes[24 ..< 71]`（47 字节），校验：

| 偏移 | 校验 | 含义 |
|---|---|---|
| `h[0:4]` | `== v ^ 0x88888888` | 头部完整性 |
| `h[33:37]` | `== "LLGB"` | 布局魔数 |
| `h[43]` | 分区表所在扇区号 | 乘以 512 得偏移 |
| `h[44]` | 分区表长度（扇区） | 当前版本固定 1 |

### 3.3 设备标识块（DRKB，扇区 11）

LBA 11 是一个 512 字节结构：

```
[0   ..< 256]  材料区（原料 + 随机数）
[256 ..< 512]  设备标识密文（256 字节）
标记：back[0:4] == "DRKB"
```

解密步骤：

```
material = back[0..<256] + vid_hex("0dd8") + pid_hex("2005") + LE64(设备总容量)
key4     = CRC32(material)                      // 4 字节
decoded  = AES_OffsetTransform(back[256..512], key4, salt="EDPSECDISK200709", offset=0)
校验 decoded[0:4] == "PDKB"
identity = decoded[4..] 截到第一个 0x00，转小写
```

得到的就是**设备标识字符串**（本盘为 `disk&ven_eaget&prod_usb_disk`）。

> 注意：这个标识**来自盘上**，不是 macOS 枚举出的 USB 序列号。
> 所以把盘插到别的机器、换一个 USB 口，标识都不变——这正是它能跨机使用的原因。

### 3.4 分区表（EDPF）

用 `identity` 再算一次 CRC32 作为密钥，解密第 `h[43]` 个扇区：

```
key4b = CRC32(identity)
table = AES_OffsetTransform(head[h[43]*512 .. +512], key4b, salt, 0)
校验 table[0:4] == "EDPF"
版本： (u16le(table,288) ^ 0x88) == 0x206
```

表里有 3 条 **96 字节**的记录，每条：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | `"EDPF"` 标记 |
| 12 | 4 | 分区类型 |
| 24 | 8 | 起始扇区 |
| 40 | 8 | 字节长度 |
| 48 | 4 | 口令 CRC32 校验值 |
| 52 | 4 | 密钥 CRC32 校验值 |
| 56 | 16 | **加密的数据密钥** |
| 88 | 1 | 算法编号（2 = SM4） |

- `kind == 2` 的那条就是**交换区**
- 本盘：起始 LBA 20480，长度 56,598,069,248 字节（约 56.6 GB）

### 3.5 口令校验与密钥展开

```
p = 口令（GBK 编码，长度 1–20 字节）
1) 校验： CRC32(p) == LE32(record[48])        // 口令是否正确
2) 展开： key = SM4_Decrypt(record[56..72], MD5(p))
3) 校验： CRC32(key) == LE32(record[52])       // 密钥是否有效
```

拿到 16 字节 `key` 之后，就可以解密整个交换区了。

**注意顺序**：先校验口令再用 MD5 解密密钥，两步都通过才继续。
程序中这两步都在内存里完成，口令和密钥都不落盘。

## 4. 密码学组件

### 4.1 CRC32（非标准变体）

标准 CRC32 是"初值 0xFFFFFFFF + 末尾取反"，但 EDP 用的是：

```c
uint32_t crc = 0;                       // 初值为 0
for (b in data) crc = table[(crc ^ b) & 0xFF] ^ (crc >> 8);
return crc;                             // 不做末尾取反
```

多项式仍是 `0xEDB88320`（反射），只是初值和收尾不同。
对本盘的 "123456789" 会得到 `0x2DFD2D88` 而不是标准的 `0xCBF43926`。

### 4.2 MD5

标准 MD5，只用于把口令变成 16 字节的 SM4 密钥。没有加盐。

### 4.3 SM4

国密 SM4（GB/T 32907），**ECB 模式、512 字节一个扇区独立处理**。
数据区没有偏移扰动，所以同一明文扇区加密后密文相同（这也解释了零块密文恒定的现象）。

实现上做了多核并行：

| 实现 | 吞吐 |
|---|---|
| 单线程 | 约 100 MB/s |
| 8 核并行 | 约 450 MB/s |

### 4.4 AES-128 + 偏移扰动（仅用于元数据）

元数据（DRKB 的标识、EDPF 分区表）用的是 AES-128 的变体：

```
AES 密钥   = salt XOR key       （salt = "EDPSECDISK200709"，16 字节；
                                  key 为 CRC32 得到的 4 字节循环使用）
对每个 16 字节块：
    tweak  = (byteOffset + pos) & 0xFFFFFFFFFFFFFFFF   // 小端 8 字节
    轮密钥 = AES 扩展密钥 与 tweak 逐字节异或（按 i % 8 循环）
    密文   = AES 加/解密该块（使用被扰动过的轮密钥）
```

因为扰动只依赖**块在缓冲区内的偏移**（`byteOffset` 固定为 0），
所以同一段元数据无论放在盘上哪个位置，解密结果都一样。

### 4.5 常量速查

| 名称 | 值 |
|---|---|
| 盐 | `EDPSECDISK200709`（十六进制 `4544505345434449534b323030373039`） |
| 元数据标记 | `$$$<digits>$$$`（偏移 2048） |
| 头魔数 | `LLGB` |
| 标识块 | `DRKB` / 解密后 `PDKB` |
| 分区表 | `EDPF` |
| 版本 | `0x206`（字段 ^ 0x88） |
| VID/PID | `0dd8` / `2005` |

## 5. 运行时架构

### 5.1 进程与权限模型

```
┌─────────────────────────────────────────────────────────┐
│ Terminal（你的终端）                                     │
│   EDP交换区.command  ← 浏览器式菜单，普通用户权限         │
└───────────────┬─────────────────────────────────────────┘
                │ 启动 / 控制文件
                ▼
┌─────────────────────────────────────────────────────────┐
│ edp-mount（守护进程，root）                              │
│   · 打开 /dev/rdiskN                                     │
│   · 解密、建镜像、调用 hdiutil 挂载                       │
│   · 监听文件系统事件，自动保存                            │
└─────────────────────────────────────────────────────────┘
```

**权限为什么需要 root**：`/dev/rdiskN` 是 `crw-r----- root:operator`，
只有 root 能写。`operator` 组成员只能读，不够用。

**免密方案**：安装时把二进制复制到 `/usr/local/libexec/edp-mount`（root:wheel 0755），
再写一条只允许运行这个程序的 sudoers 规则：

```
<用户名> ALL=(root) NOPASSWD: /usr/local/libexec/edp-mount
```

这样：
- Mac 登录密码**不需要保存到任何地方**
- 规则只能执行这一个固定路径的程序，不能用来干别的
- 用户无法改写该程序（root 所有）

**密码存放**：交换区口令存在 **macOS 钥匙串**（服务名 `edp-exchange-password`），
由系统加密保护，U 盘上不留明文。

### 5.2 挂载流程（时间轴）

```
1. 打开原始设备
   · 先尝试 O_RDWR；若 EBUSY（启动区还挂着）→ 强制卸载该磁盘上的卷后重试
2. 读前 32KB，解析元数据（见第 3 节）
   → exchange_offset / exchange_size / algorithm / EDPF 记录
3. 从 stdin 读口令（脚本通过 FIFO 传入，不进命令行、不进环境变量）
4. 校验口令 → 展开 16 字节数据密钥
5. 检查本地工作镜像是否可用：
   · 有 + 快速校验通过 → 复用（约 2 秒）
   · 有 + 快速校验失败 → 全量校验 / 增量同步
   · 没有 → 全量重建（解密所有已分配簇）
6. 写镜像文件（MBR + exFAT 分区），hdiutil attach，diskutil mount
7. 打开访达窗口（带侧边栏）
8. 进入事件循环：等待保存 / 退出 / 卷被弹出
```

### 5.3 读路径

```
访达读文件
   ↓
macOS exFAT 文件系统
   ↓
本程序的 Img_Info::read(offset, size)     ← 自定义读取器
   ↓
按 1MB 分块从 /dev/rdiskN 读密文
   ↓
SM4 解密（多核并行）→ 缓存
   ↓
返回明文给内核
```

- 缓存只保留最近 24 个 1MB 块，内存占用恒定
- 读吞吐受 U 盘限制（实测 35~100 MB/s）

### 5.4 写回流程（保存）

**① 计算差异**

```
对镜像的每个已用区间，按 4MB 分块：
    读 镜像块（新内容）
    读 基线块（上次保存时的内容）
    逐 512 字节比较，记录不同的扇区偏移
```

基线镜像就是"上次成功写回后的样子"，有它才能只写变化的部分。

**② 落盘日志**

只记录**扇区偏移列表**（8 字节/扇区），不存数据：

```
"EDPJRN02" + 扇区数(4B) + 偏移(8B) × N
```

旧内容不需要存，回滚时用基线镜像重新加密算出来即可。
（早期版本存前后密文，500MB 的保存要写 583MB 日志，现在只要 8MB。）

**③ 批量写入 + 抽样校验**

```
攒满 16MB → 一次性写入设备
每 4 批做一次回读校验（对比刚写入的密文本身，不重读镜像）
最后一批必校验
```

为什么要批量：USB 设备在读写之间切换代价很高。
为什么要对比"刚写入的密文"：如果改比"重新读镜像再加密"，用户保存过程中编辑就会误报失败。

**④ 完成**

- `fsync` + `F_FULLFSYNC`（部分设备不支持，静默忽略）
- 用镜像覆盖基线
- 日志改名为 `.jrn.done`
- 写入摘要：`last_save_mb / secs / mbs`

### 5.5 崩溃恢复

启动时扫描 `回滚记录/*.jrn`：

1. **先抽样核对**：取最多 64 个偏移，看设备当前内容是否已经等于基线
   - 如果都相等 → 说明无需回滚（可能是历史遗留日志）→ 直接标记 `.stale` 跳过
2. 否则逐块用基线重新加密旧内容写回设备
3. 标记 `.rolledback`

> 这一步很关键：早期版本会无脑回滚，而那时基线可能已经被后续保存更新过，
> 结果用新基线写旧日志，把数据写乱（曾导致一个文件丢失）。

### 5.6 自动保存

基于 **FSEvents**（内核文件系统事件），不是定时轮询：

```
文件被写入
   ↓
FSEvents 回调（忽略 .Spotlight-V100 / .fseventsd / .Trashes 的噪音）
   ↓
置 dirty 标记，记录最后变更时间
   ↓
静止 1 秒（防抖，等这一波写操作收尾）
   ↓
触发保存（不卸载卷 → 访达不闪断）
```

两个可调参数：

| 参数 | 默认 | 作用 |
|---|---|---|
| `idle=` | 1.0 秒 | 静止多久触发保存（最小 0.5） |
| `max=` | 60 秒 | 连续写入时，最长多久强制落盘一次 |

`max` 解决的是"拷一个 5GB 大文件、3 分钟不落盘"的问题。

## 6. 性能设计与实测

### 6.1 三个关键优化

| 优化 | 原因 | 效果 |
|---|---|---|
| **两级校验** | 每次挂载都全量比对 1.6GB 太慢 | 挂载 20s → **2s** |
| **批量写入** | 512 字节一次 `pwrite`，USB 只有 0.7MB/s | 507MB 从 7 分钟 → **28 秒** |
| **多核 SM4** | 单线程只有 100MB/s | 450MB/s |

### 6.2 快速校验

挂载时不全量比对，只检查：

- 元数据区（引导扇区 + FAT 区，约 3MB）
- 根目录簇
- 跨数据区的 **32 个 256KB 采样窗口**（约 8MB）

合计约 11MB。命中就直接复用镜像；不命中才做全量校验或增量同步。

### 6.3 增量同步

如果镜像与盘不一致但**本地没有未保存修改**，不重建整盘，而是：

```
只把「盘上与基线不同的扇区」解密后写进镜像，然后对齐基线
```

实测从"整盘重建 20 秒"降到"增量同步 1 秒"。

### 6.4 内存控制

| 阶段 | 内存（RSS） |
|---|---|
| 空闲 | 9 ~ 12 MB |
| 读 289MB 大文件 | 11.5 MB（不变） |
| 写 300MB 并保存 | 11.5 MB（峰值） |

实现要点：
- 镜像读写用 `pread`/`pwrite` 到固定缓冲区，**不映射文件页**
- 所有处理按 4MB / 16MB 分块，处理完立即释放
- 解密缓存限制 24 个块

> 试过但放弃的优化：给 4MB 块算 CRC32 做差异缓存。
> Swift 里 CRC32 扫 1.6GB 要 4.9 秒，比直接 `memcmp` 慢 5 倍，已回退。

### 6.5 实测数据

```
挂载：2 秒（快速校验命中）
重挂：1 秒
保存 90MB：比对 2.6s + 写入 2.9s + 校验 0.0s
保存 300MB：比对 1.0s + 写入 9.5s（约 31MB/s）+ 摘要 13s
```

**瓶颈始终是 U 盘本身的写入速度**，实测在 8~31 MB/s 之间波动
（与 USB 口、线材、设备控制器有关）。软件侧（比对+加密+校验）通常只占 1~3 秒。

## 7. 安全设计

| 项目 | 做法 |
|---|---|
| 口令传输 | 脚本通过 **FIFO** 传给守护进程，不出现在命令行参数、环境变量、日志中 |
| 口令存储 | macOS 钥匙串（系统加密） |
| Mac 密码 | **不保存**，靠 sudoers 免密规则 |
| 密钥生命周期 | 只在守护进程内存中，退出时释放；镜像文件权限 0600 |
| 明文副本 | 本机镜像含明文，但目录 0700 / 文件 0600，可随时 `rm -rf` 清除 |
| U 盘写入范围 | 只写交换区（`exchange_offset` 起的范围），绝不碰启动区/保密区/MBR |
| 网络 | 全程不联网 |
| 回滚保护 | 每次写前落日志，失败自动回滚 |

**已知的固有风险**：本机镜像里是明文数据。这是用户态模拟无法避免的代价——
只要没有内核驱动，就必须在某个地方放一份明文副本。

### 8.3 工作目录内容

```
~/Library/Caches/edp-mount/
├── 工作镜像.raw          解密后的工作副本（逻辑 56.6GB，稀疏占用约 1.6GB）
├── 基线镜像.raw          上次写回时的对照副本
├── 回滚记录/             每次写回的扇区偏移日志（.jrn / .jrn.done / .stale）
├── manifest.json         交换区偏移/大小/镜像偏移
├── state.json            实时状态（阶段、进度、速度）—— 脚本读它渲染界面
├── ctrl                  脚本 → 守护进程的控制通道
├── autosave.conf         自动保存配置
├── edp.pid               守护进程 PID
└── EDP交换区.command     脚本自身副本
```

脚本与守护进程通过**文件**通信，而不是 socket/HTTP：
- `ctrl`：脚本写入 `save` / `quit` / `eject` / `discard`
- `state.json`：守护进程写入，脚本轮询渲染

### 8.4 配置文件

`~/Library/Caches/edp-mount/autosave.conf`：

```sh
off            # 关闭自动保存
on             # 开启（默认）
idle=0.5       # 写入后静止多久触发保存（默认 1.0，最小 0.5）
max=30         # 连续写入时最长多久强制保存一次（默认 60）
```

## 9. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `无法以读写方式打开设备` | 启动区还挂着 / 权限不足 | 程序会自动强制卸载后重试；仍失败则确认有 root |
| `交换区密码校验未通过` | 口令错 | 删除钥匙串条目后重新运行安装脚本 |
| `设备元数据头校验失败` | 元数据被改动 / 盘不对 | 确认是这块盘 |
| `U 盘与保留的工作镜像不同` | 上次异常退出或换机使用 | 新版会自动增量同步；有未保存修改时先备份 |
| 挂载后没有访达窗口 | Finder 隐藏了工具栏 | 程序每次会强制 `toolbar visible = true` |
| 保存很慢（<10MB/s） | USB 口/线材是 2.0，或设备本身慢 | 换 USB 3.0 数据线、直插机身口 |
| 设备从系统消失 | 强制卸载/弹出后 USB 重新枚举 | 拔插一次；`diskutil mountDisk diskN` 可恢复 |

## 10. 已知限制

1. **不是实时写入**
   用户态方案必须先解密到副本再回写，无法像内核驱动那样写穿。
   最接近的做法是自动保存（约 1~2 秒延迟）。

2. **需要本机磁盘空间**
   工作镜像逻辑 56.6GB，实际占用约等于盘上已用数据（当前约 1.6GB）。

3. **明文副本落本机**
   无法避免（除非有内核驱动）。可随时删除，下次插盘自动重建。

4. **不支持保密区**

5. **设备自身稳定性**
   测试中多次观察到该 U 盘从 USB 总线掉线（日志显示设备 `Disappear`）。
   可能与线材/接口有关，也与廉价加密控制器的写缓存策略有关。

6. **不支持 `F_FULLFSYNC`**
   该盘返回 ENOTTY，无法强制刷设备缓存。所以**保存后请走"保存并弹出"再拔线**。

## 12. 附录：数据结构速查

### 12.1 元数据头（解混淆后）

```
h[0:4]     = v ^ 0x88888888      （校验）
h[33:37]   = "LLGB"
h[43]      = 分区表所在扇区
h[44]      = 分区表扇区数（=1）
```

### 12.2 EDPF 记录（96 字节）

```
+0   4   "EDPF"
+12  4   kind         (2 = 交换区)
+24  8   起始扇区
+40  8   字节长度
+48  4   CRC32(口令)
+52  4   CRC32(数据密钥)
+56 16   SM4_Encrypt(数据密钥, MD5(口令))
+88  1   算法        (2 = SM4)
```

### 12.3 回滚日志（EDPJRN02）

```
+0   8   "EDPJRN02"
+8   4   扇区数 N（小端）
+12  8*N 每个扇区在交换区内的偏移
```

### 12.4 state.json 字段

```
read_mbs / write_mbs  实时读/写速度

```
