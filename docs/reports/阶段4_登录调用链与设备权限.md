# 阶段 4：登录调用链与实际权限阻碍

日期：2026-10-26。目标仍为在 Mac 上通过正常认证使用交换区，当前尚未实现。

## 已完成的独立分析

- 改用沿直接分支遍历的静态指令追踪，避免将跳过的内嵌字节当作可执行指令。该追踪不执行目标程序，不处理全部间接跳转与异常边，因而仍不是完整控制流恢复。
- `UserLogin` 的候选入口为控制 DLL 首选 VA `0x10026500`，取得 1,262 条可达指令、134 个调用记录。
- `WSTUserLogin` 的候选入口为 `0x100282a0`，取得 387 条可达指令、48 个调用记录。
- 两条路径分别在 `0x100275d1`、`0x1002873d` 调用全局指针 `0x10095120`。该指针此前已经由 GetProcAddress 的 EdpMountFile 解析结果赋值。
- 普通登录例程中的日志明确提及 PartitionSize、StartSector、FileKey，并构造物理磁盘路径。这支持“主机侧挂载参与访问”的判断，不能据此断言固件认证后会直接暴露标准分区。
- 已提取挂载 DLL 的核心例程检查服务句柄并调用 DeviceIoControl。驱动是否适用于实际设备、其他路径是否存在，仍需进一步核实。

对上述两个调用点作了脚本断言，并验证跳过的内嵌数据不进入对应参数处理例程的可达指令输出。所有产物位于 `静态分析证据/阶段4/`。

## 实际设备读取尝试与结果

1. 通过 macOS 原生管理员授权对话框执行限定读取脚本，没有使用聊天中出现的密码。
2. 第一次执行遇到 Documents 下虚拟环境配置读取被系统拒绝；未进入磁盘读取。
3. 将限定脚本放在临时目录，以系统 Python 隔离方式执行，脚本成功运行到只读打开设备这一步，但 `/dev/rdisk4` 返回 `PermissionError: [Errno 1] Operation not permitted`。
4. 尚未成功读取首扇区，没有写盘、尝试 U 盘口令、发送厂商命令或修改磁盘权限。

管理员授权不足以解决当前访问限制。错误与 macOS 隐私权限限制相符，但还需在权限调整后重试，不能宣称已完全确定其原因。已打开系统设置的完全磁盘访问权限页面。

## 继续真实设备验证所需的本机操作

在“系统设置 → 隐私与安全性 → 完全磁盘访问权限”中，为实际承载本任务的 Codex 应用开启权限；系统如提示退出并重新打开应用，按系统提示操作。密码仅在系统授权窗口输入。

此操作由系统界面完成，本轮没有自行修改 TCC 数据库、降低系统安全设置或改动设备访问权限。权限满足后，先重新校验 U 盘身份，再仅读取分区和必要元数据；当前仍不具备直接运行解锁命令的依据。
