>
> 保存只刷新交换区及其本机镜像，不再调用全局 `sync()`；耗时从保存请求处理开始计算，包含刷新、写入、全部改动数据回读和收尾。所有本次写入的区间都会完整回读，零改动只显示检查完成。

# U 盘启动程序（独立挂载器）

## 交付内容

已写入 U 盘「启动区」（`/Volumes/启动区`）：

| 文件 | 说明 |
|---|---|
| `edp-mount` | 通用二进制（arm64 + x86_64，400 KB），零外部依赖 |
| `启动交换区.command` | 双击启动：问 U 盘密码 → 管理员授权 → 挂载到访达 |
| `保存到U盘.command` | 把访达里的修改加密写回 U 盘并回读校验 |
| `卸载交换区.command` | 询问是否保存后卸载 |
| `使用说明.txt` | 终端用户说明 |

本目录保留同一份源码与构建产物。

## 技术实现

全部用 Swift 重写，**不依赖** Python / pytsk3 / 项目目录 / 网络：

- `crc32`（参考实现用的变体：寄存器从 0 起算、不做最终异或）
- `md5`、`aes-128`（含偏移扰动变体）、`sm4`
- 设备元数据解码：`$$$<n>$$$` 头 → 逐字异或 → `LLGB` 校验 →
  `DRKB` 设备标识记录 → `crc32(标识)` 作密钥 → `PDKB` →
  `EDPF` 分区表 → 取交换区起点/大小/算法
- 口令校验与密钥解包：`crc32(口令)` 比对 → `SM4(记录[56:72], MD5(口令))` → `crc32(密钥)` 比对
- exFAT 解析与稀疏工作镜像（只解密已分配簇，约 12 MB）
- `hdiutil`/`diskutil` 挂载到访达；写回前把受影响扇区原始密文写入回滚记录，写入后逐扇区回读校验

## 保存：写入后即时落盘

采用 **FSEvents 事件驱动**，不是定时轮询：

- 文件一写入 → 事件触发 → 1.5 秒防抖（等这一波写操作收尾）→ 立即加密写回 + 逐扇区回读校验
- 真机实测：**写入/删除后约 3 秒完成保存**，期间卷始终在线（不卸载、访达不闪断）
- 连续大量写入时会等这一波写完再落盘，避免反复写同一批扇区
- 另有 30 秒一次的镜像摘要兜底，防止极端情况下漏事件
- 手动菜单里仍可「立即保存」

## 单一入口脚本

`EDP交换区.command` 一个脚本完成全部操作，挂载后提供菜单：

```
1) 立即保存
2) 保存并退出（U 盘继续插着）
3) 保存并弹出（可安全拔线）
4) 不保存直接退出
```

也可以直接在访达里弹出「交换区」：工具会做最后一次保存，并把整块 U 盘安全弹出。
真正执行 `diskutil eject` 是在关闭原始设备句柄之后，避免 `Resource busy` 导致弹不掉。

## 换机/换系统后的兼容（永不拦截挂载）

如果 U 盘在其他电脑（如 Windows 客户端）上被修改过，本机工作镜像会与盘不一致。
现在**不会报错、不会阻止挂载**：

- 一律以 **U 盘为准重建**工作镜像
- 若旧镜像里还有未保存的修改，先整体备份到
  `~/Library/Caches/edp-mount-backup-<时间>/`，再重建（脚本只保留最近 2 份）
- 真机验证：故意改坏基线后重新挂载 → 正常挂载，日志提示已按 U 盘重建并备份

另外处理了 `SIGHUP`：直接关掉终端窗口也会先保存再退出，不会丢未落盘的修改。

## 免密码方案（一次性配置）

`安装免密码.command` 做两件事（只需管理员密码一次）：

1. 把 `edp-mount` 安装到 `/usr/local/libexec/edp-mount`（root:wheel 0755），
   并写入 `/etc/sudoers.d/edp-mount`：
   ```
   <用户名> ALL=(root) NOPASSWD: /usr/local/libexec/edp-mount
   ```
   → 之后 `sudo -n` 即可运行该程序，**Mac 登录密码不需要保存到任何地方**。
   规则只允许运行这一个 root 所有的固定路径程序，用户不能改写它。
2. 把 U 盘交换区密码存入 macOS 钥匙串（服务名 `edp-exchange-password`），
   → 明文不落在 U 盘上，换机也读不到。

主脚本运行逻辑：

- 钥匙串有密码 → 直接用；没有才弹窗
- 帮助程序存在且版本一致 → `sudo -n` 静默运行
- 帮助程序缺失/版本不同 → 回退到 sudo 交互（并提示可运行安装脚本更新）

实测：装好后运行 `EDP交换区.command` 全程零输入，直接挂载成功。

撤销：

```sh
sudo rm /etc/sudoers.d/edp-mount /usr/local/libexec/edp-mount
security delete-generic-password -s edp-exchange-password
```

## 大文件传输修复（2026-10-26）

一次写入 218MB + 289MB 时暴露出三个问题，均已修复：

1. **写回太慢**：原来是每 512 字节一次 `pwrite`，实测仅 0.7MB/s。
   改为把连续扇区合并成最多 4MB 的批量写 → **507MB 从 7 分钟降到 28 秒（≈18MB/s）**，
   并在 state.json 里输出百分比进度。
2. **重建镜像出现零数据（严重）**：解密缓存淘汰时可能把"刚读进来的块"也淘汰，
   导致后续读取返回空 → 重建出的镜像里大文件后半段全是零。
   修复后重建哈希与写入值完全一致（已用 100MB / 218MB / 289MB 文件反复验证）。
3. **挂载态读镜像不可靠**：hdiutil 的写缓存会让读到的镜像文件落后于实际内容，
   甚至 `sync()` / `sync_volume_np()` 也无法保证。已改回"先卸载 → 写回 → 再挂回"，
   但配合批量写入，卸载窗口很短。

另外：
- 回滚日志改为只记录偏移（8 字节/扇区），不再存 before/after 明文密文，体积从 583MB 降到约 8MB
- 启动时自动回滚未完成的写回（用基线镜像重算旧密文）
- 保存前若发现未完成日志，会先恢复再继续


## 挂载速度优化（2026-10-26）

原来每次挂载都要把整个已用区域（约 500MB）从 U 盘读回逐字节校验，USB 只有 30MB/s → 十几秒。

改为**两级校验**：

1. **快速校验**：只比对元数据区（引导扇区 + FAT 区）+ 根目录簇 + 跨数据区的 32 个 256KB 采样窗口（约 11MB）
2. 匹配 → 直接复用工作镜像；不匹配 → 才做全量校验/增量同步

实测：**挂载 20 秒 → 2 秒**，连续三次命中。

## 自动保存优化（2026-10-26 晚）

| 优化 | 说明 |
|---|---|
| 竞态修复 | 写入后用「刚写入的密文」逐块回读校验，不再重读镜像 → 保存时继续编辑不会误报"回读不一致" |
| 持续写入也会落盘 | 新增 `max=` 参数（默认 60 秒）：即使文件一直在变，也会强制保存一次 |
| 噪声过滤 | 忽略 `.Spotlight-V100` / `.fseventsd` / `.Trashes` 的系统写入，不再触发无谓保存 |
| 内存有界 | 4MB 分块处理，RSS 稳定 7~11MB（修复前 1.6GB） |
| 失败日志标记 | 保存失败回滚后把日志标记 `.rolledback`，启动时不再重复回滚（此前因此丢过一个文件） |
| 陈旧日志识别 | 启动回滚前抽样核对设备，已一致则跳过，绝不用新基线写旧日志 |

**放弃的优化**：块哈希缓存。实测 Swift 里 `crc32` 扫 1.6GB 要 4.9 秒，比直接 `memcmp` 慢 5 倍，已回退。

### 实测

- 自动保存延迟：写入后约 **2.5 秒**（1s 防抖 + 1.1s 比对）
- 比对耗时：**1.0 秒**（1.6GB 镜像）
- 内存：**7 MB**

### 可调参数（`~/Library/Caches/edp-mount/autosave.conf`）

```sh
off            # 关闭自动保存
idle=0.5       # 写入后静止多久触发保存（默认 1 秒，最小 0.5）
max=30         # 连续写入时最长多久强制保存一次（默认 60 秒）
```
